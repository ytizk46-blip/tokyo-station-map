# 東京駅 3Dマップ

東京駅とそのまわりの地下通路の 3D マップと、ルート探索の部分です。国土交通省の「東京駅周辺屋内地図オープンデータ」から作っています。

出口案内アプリ「構内ナビ」（卒業研究の試作）から、画面（ログイン・検索など）と PWA を除き、マップのデータと 3D 表示だけを取り出したものです。

## 使い方

Node.js（v20 以降）が必要です。

```
npm install       # 最初の1回だけ
npm run dev       # 開発用サーバーを起動（http://localhost:5173）
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 3Dマップを表示する（スマホの実機は `npm run dev -- --host`） |
| `npm test` | ルート探索・データ・一人称・自由に歩く計算・行き先の検索のテストを実行する |
| `npm run data` | 駅のデータ（`src/data/tokyo-3d.json` と `src/data/tokyo.json`）を元データから作り直す |

### 3Dマップの操作

- 3人称：マウスで回す・ホイールで拡大と縮小。左上のボタンで表示する階（全階／1F／B1／B2）を切り替える
- 地点をクリックすると、名前・種類・階・id を下に出し、自分の位置をそこへ移す
- 「1人称で歩く」：WASD か矢印キーで歩き、Space で近くの階段・エスカレーター・エレベーターに乗る。「3人称に戻る」で元の表示へ

## ファイルの構成

```
index.html                  3Dマップを表示するページ
src/
  map3d.js                  3Dマップの表示と操作（3人称・自由に歩く1人称・ルートをたどる1人称）
  station-model.js          床・部屋・柱や壁の多角形を押し出して立体にする
  interior.js               1人称の駅の中の見た目（タイルの床・天井の蛍光灯・壁）
  free-walk.js              自由に歩くときの位置の計算（壁の当たり判定・階段の近くか）
  walkthrough.js            ルートを自動でたどる一人称
  walk-grid.js              1人称で歩ける場所のマス目（0.5m 四方）の書き出し・読み込み
  route-finder.js           ルート探索（ダイクストラ法）と道順の文章作り
  places.js                 行き先（出口・入口と建物）の一覧と検索
  map.css                   3Dマップの文字（地点の名前など）の見た目
  data/tokyo-3d.json        3Dマップとルート探索のデータ（npm run data で生成）
  data/tokyo.json           行き先の検索用データ（npm run data で生成）
tools/
  build-tokyo-3d.mjs        駅のデータを作るスクリプト
  shapefile.mjs             Shapefile を読む小さな部品（追加のソフトを入れずに済むよう自作）
tests/                      自動テスト
```

## データについて

駅のデータは、G空間情報センターの [国土交通省「東京駅周辺屋内地図オープンデータ」](https://www.geospatial.jp/ckan/dataset/mlit-indoor-tokyo-r2)（令和2年度更新版、Shapefile）から `tools/build-tokyo-3d.mjs` で作っています。`src/data/` の JSON は生成物なので、手で直さずにスクリプトを直して `npm run data` で作り直します。

- 元データ（約43MB）は git に入れません。ダウンロードして展開したフォルダを `npm run data -- <フォルダ>` で渡します。省略するとプロジェクトと同じ階層の `shapefile/東京駅周辺屋内地図オープンデータ（Shapefile）` を読みます
- 部屋・設備の種類のコード（Space の B001、Facility の F108 など）は、国土地理院「階層別屋内地理空間情報データ仕様書（案）」の別表によります
- **使っているもの**：床（Floor）、部屋・空間（Space）、柱や壁（Fixture）、区画の名前（Segment）、出口（Facility の F108）、建物の入口（Facility の F017）、改札（Opening の名前）、歩行者ネットワーク（nw）
- **使っていないもの**：図面の線（Drawing）、点字ブロック（TWSI）

データを作るときにしていること：

- 階は「1階・地上」（元データの 1 と 0＝グランドレベル）、「地下1階」、「地下2階」の3つにまとめる。階段の踊り場（1.5 などの小数の階）は取り除き、両側を直接つなぐ
- ほかとつながっていない小さな歩行者ネットワークは、ルートを探せないので除く
- 出口・入口・改札は、40m 以内のいちばん近い通路の地点につなぐ。同じ名前が近くに2つ以上あるときは、通路にいちばん近い物を1つだけ使う
- 閉鎖中の出口は使わない。元データの「東京メロト」は「東京メトロ」に直す
- 歩きにくさの倍率（ルートのコスト）：階段 1.5、エスカレーター 1、エレベーター 5
- 最後に「全部の改札 × 全部の行き先」でルートが見つかるかを確かめる

座標の決まり：単位はメートル。原点は JR 東京駅（139.7671, 35.6812）、X は北がプラス、Z は東がプラス。表示上の階の間隔は 30m。

**推定していること**：元データには、地下鉄の出口がどの駅の物かが入っていません。そこで、駅のおおよその中心から 350m 以内なら「A1出口（銀座駅付近）」のように近い駅の名前を、それより遠いときは「東京駅の北東」のような方角を付けています。駅の中心の位置は推定なので、実際とは違う場合があります（データ上は `"estimated": true`）。

**注意**：

- データは改札の外だけです。ホームや改札の中は入っていません
- 平面の地図を階ごとに押し出しただけなので、部屋の高さや階の間隔は見やすさのために決めた値です
- お店の名前は元データに入っていません

## ライセンス・出典の表示

国土交通省「東京駅周辺屋内地図オープンデータ」（G空間情報センター）を加工して作成。利用条件はデータセットのページで確認してください。
